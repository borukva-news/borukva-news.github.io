# Borukva News

Сайт новин Борукви: вебгазети, інтерактивні сторінки випусків, каталог 3D-персонажів і редактор пропозицій новин.

**Сайт:** [borukva-news.github.io](https://borukva-news.github.io/)

## Можливості

- Головна сторінка з навігацією, каруселлю випусків і рядком останніх новин.
- Перегляд випусків газети, повноекранний режим і клікабельні хотспоти.
- UV-випуск із ефектом ультрафіолетового ліхтарика.
- Каталог персонажів і картки з інтерактивними 3D-моделями та скінами.
- Генератор сторінок новин із можливістю надіслати пропозицію на модерацію.
- Express API для хотспотів, пропозицій новин і взаємодії з даними у GitHub.
- Окремий skin proxy для отримання скінів Minecraft.

## Технології та структура

- `client/` — React SPA на Vite, стилі й зображення сайту.
- `server/` — Node.js / Express API; запускається окремо від фронтенду.
- `skin-proxy/` — окремий Node.js API для отримання Minecraft-скінів.
- `client/src/data/issues.js` — конфігурація випусків, посилань і новин головної сторінки.
- `client/src/data/characters.js` — дані персонажів, включно з описами й моделями.
- `client/public/assets/` — статичні зображення, шрифти, звуки та 3D-моделі.
- `.github/workflows/deploy.yml` — CI-збірка та деплой фронтенду на GitHub Pages.

## Локальний запуск

Потрібен Node.js 20 або новіший та npm.

```sh
cd client
npm ci
npm run dev
```

Vite покаже локальну адресу (зазвичай <http://localhost:5173>). У режимі розробки запити `/api` проксійовані на production API, заданий у `client/vite.config.js`.

### Запуск API локально

API потрібен для роботи з хотспотами та надсилання нових пропозицій. Для повної локальної роботи запустіть його в окремому терміналі:

```sh
cd server
npm ci
```

Створіть `server/.env` на основі `server/.env.example`, заповніть потрібні змінні та запустіть:

```sh
npm run dev
```

За замовчуванням API працює на порту `3000`; перевірка стану: `http://localhost:3000/api/health`.

Щоб фронтенд звертався до локального API, створіть `client/.env.local`:

```dotenv
VITE_API_URL=http://localhost:3000
VITE_BACKEND_URL=http://localhost:3000
```

`VITE_API_URL` використовується для хотспотів, а `VITE_BACKEND_URL` — генератором новин. Якщо потрібні лише локальні сторінки без локального API, додаткові змінні задавати не потрібно.

## Змінні середовища API

Значення з префіксом `VITE_` доступні в клієнтському коді — не зберігайте в них секрети. GitHub-токени, ключі пошти та секрет модерації задаються лише в `server/.env` або в налаштуваннях хостингу.

| Змінна | Призначення |
| --- | --- |
| `PORT` | Порт Express API; локальне значення за замовчуванням — `3000`. |
| `GITHUB_OWNER` | Власник GitHub-репозиторіїв; за замовчуванням `borukva-news`. |
| `NEWS_DATA_REPO` | Репозиторій даних і хотспотів; за замовчуванням `news-data`. |
| `CUSTOM_NEWS_REPO` | Репозиторій користувацьких новин; за замовчуванням `custom-news`. |
| `GITHUB_TOKEN` | Спільний GitHub-токен як запасний варіант для обох репозиторіїв. |
| `NEWS_DATA_GITHUB_TOKEN` | Окремий токен для `NEWS_DATA_REPO`. |
| `CUSTOM_NEWS_GITHUB_TOKEN` | Окремий токен для `CUSTOM_NEWS_REPO`. |
| `API_PUBLIC_URL` | Публічна адреса API; використовується у посиланнях модерації. |
| `FRONTEND_URL` | Адреса фронтенду для налаштування CORS. |
| `MODERATION_SECRET` | Секрет для підтвердження та відхилення новин. |
| `MODERATOR_EMAIL` | Адреса модератора. |
| `RESEND_API_KEY`, `RESEND_FROM` | Надсилання листів через Resend. |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` | Альтернативне надсилання листів через SMTP. |

Для створення/збереження даних API потрібні відповідні GitHub-токени з правами запису в налаштовані репозиторії. Не додавайте `.env` до Git.

## Перевірка, збірка та деплой

Команди запускаються з `client/`:

```sh
npm run lint
npm run build
npm run preview
```

`npm run build` створює production-версію в `client/dist/`. GitHub Actions збирає її з Node.js 20 і публікує на GitHub Pages після push у гілку `main` або ручного запуску workflow.

API та skin proxy розгортаються окремо. Конфігурація Render для skin proxy розташована в `skin-proxy/render.yaml`.
